# Interview Grill

## Overview

USER 면접 준비를 대충 위로하지 않고 빡세게 털어보는 스킬이야. JD, 회사 맥락, USER 이력, 이전 답변을 보고 약한 지점을 예측한 뒤, **한 번에 한 질문**만 던진다. 질문마다 추천 프레이밍을 같이 주고, USER 답을 받은 뒤 꼬리질문으로 압박한다.

목표는 “그럴듯한 AI 답변”이 아니라 면접장에서 실제로 버틸 수 있는 답변이야. 과장하지 않고, USER 경험을 선명하게 만들고, 약점은 숨기지 말고 안전하게 다루게 만든다.

## When to Use

구직 중 다양한 면접 단계에서 사용해.

- JD를 보고 예상 질문과 약점을 뽑아야 할 때
- 서류 합격 후 1차/실무/기술/컬처핏 면접을 준비할 때
- 자기소개, 지원동기, 이직사유, 강점/약점 답변을 다듬을 때
- 프로젝트 경험을 STAR/CAR 구조로 정리해야 할 때
- 기술 면접에서 깊게 파고들 질문을 연습해야 할 때
- 과거 면접에서 망한 답변을 복기하고 다음 답변을 만들 때
- 회사/직무별로 답변 톤과 강조점을 바꿔야 할 때
- USER이 “면접관처럼 압박해줘”, “꼬리질문 해줘”, “내 답변 찢어줘”라고 할 때

Don't use for:

- 허위 경력, 과장된 성과, 실제로 안 한 일을 꾸며내는 요청
- 단순 이력서 문장 교정만 필요한 경우
- 회사 조사가 핵심인 경우에는 먼저 `company-interview-research`를 함께 고려해

## Workflow

### 1. 자료를 모은다

가능하면 먼저 확인해.

- JD/공고 원문
- 회사명, 팀, 직무 레벨
- USER 이력서/포트폴리오/프로젝트 요약
- 면접 단계: HR, 실무, 기술, 임원, 컬처핏
- 이전 면접 질문/답변/피드백

자료가 없으면 없는 상태로 시작하되, 가정은 명시해.

Completion criterion: 어떤 면접을 준비하는지와 가장 중요한 평가축이 잡혀 있어야 한다.

### 2. JD 분석

JD에서 신호를 뽑아.

- 핵심 업무: 입사 후 바로 해야 할 일
- 필수 역량: 없으면 탈락 가능성이 큰 것
- 우대 역량: 있으면 차별화되는 것
- 숨은 평가축: 오너십, 협업, 모호함 처리, 속도, 품질, 커뮤니케이션
- 위험 신호: 과도한 범위, 애매한 직무, 레거시/운영 부담, 높은 자율성 요구

짧게 정리해.

```md
JD 핵심 신호
- 이 포지션은 <핵심 역할>을 본다.
- 가장 세게 물을 가능성이 큰 축은 <A/B/C>다.
- USER 답변에서 위험한 빈틈은 <X/Y>다.
```

Completion criterion: 첫 질문을 고를 수 있을 만큼 평가축과 위험 지점이 정리되어야 한다.

### 3. 취약점 예측

USER의 이력과 JD 사이의 간극을 먼저 찌른다.

- 경험은 있는데 성과 수치가 약한가?
- 기술 키워드는 있는데 깊이 설명이 약한가?
- 리더십/협업 사례가 추상적인가?
- 이직사유가 방어적으로 들릴 위험이 있나?
- 직무 전환이면 “왜 지금, 왜 이 역할”이 약한가?
- 실패/갈등/약점 답변이 너무 예쁘게 포장되어 있나?

Completion criterion: 오늘 grill 할 우선순위 3개 이하가 정해져야 한다.

### 4. 한 번에 한 질문만 던진다

기본 형식은 이거야.

```md
질문 1 — <면접관이 실제로 물을 법한 날카로운 질문>

왜 위험하냐면: <이 질문에서 USER이 털릴 수 있는 지점>

추천 프레이밍: <답변 구조/강조점/피해야 할 말>

USER 답변해봐. 답 주면 내가 면접관처럼 꼬리질문하고, 그다음 수정안을 줄게.
```

규칙:

- 질문은 하나만. 자기소개+지원동기+프로젝트를 한꺼번에 묻지 마.
- 답변 예시는 주되, USER 답을 대신 완성해버리지 마.
- USER이 먼저 말하게 하고, 그 답을 기준으로 교정한다.
- 면접관처럼 압박하되 모욕하지 마.
- 답변이 너무 AI 같으면 즉시 잡아낸다.

Completion criterion: USER이 1~2분 답변으로 바로 연습할 수 있는 질문이어야 한다.

### 5. 꼬리질문으로 깊이를 확인한다

USER 답변을 들은 뒤 하나만 더 파고든다.

- “그때 USER이 직접 한 결정은 뭐였어?”
- “성과가 좋아진 걸 어떻게 측정했어?”
- “반대 의견이 있었으면 어떻게 설득했어?”
- “기술적으로 제일 어려운 지점은 뭐였고, 대안은 뭐였어?”
- “지금 다시 한다면 뭐를 다르게 할 거야?”
- “그 경험이 이 회사/JD랑 어떻게 연결돼?”

Completion criterion: 답변이 실제 경험 기반인지, 깊이가 있는지, JD와 연결되는지 확인되어야 한다.

### 6. 피드백은 직설적으로 준다

피드백은 칭찬부터 길게 하지 말고 바로 고친다.

```md
피드백
- 좋은 점: <살릴 포인트 1개>
- 위험한 점: <탈락 신호가 될 수 있는 부분>
- 고칠 방향: <구체 수정>
- 추천 답변 뼈대: <30초/60초 구조>
```

가능하면 답변을 두 버전으로 정리해.

- **짧은 버전:** 30초, HR/아이스브레이크용
- **깊은 버전:** 90초, 실무/꼬리질문용

Completion criterion: USER이 바로 다시 말해볼 수 있는 수정 구조가 있어야 한다.

### 7. 반복 드릴

하나의 질문은 다음 루프로 끝낸다.

1. 질문
2. USER 답변
3. 꼬리질문
4. USER 추가 답변
5. 피드백
6. 추천 답변 뼈대
7. 다시 말해보기 또는 다음 질문 선택

다음 질문으로 넘어가기 전에 물어봐.

- “이 답변 한 번 더 다듬을래, 아니면 다음 질문 갈까?”

Completion criterion: USER이 답변을 개선했거나, 의식적으로 다음 질문으로 넘어가겠다고 선택해야 한다.

## Interview Question Bank examples

### 경험 질문

- “가장 임팩트 있었던 프로젝트 하나만 골라서 말해봐. 근데 팀 성과 말고 USER이 직접 바꾼 걸 중심으로.”
  - 추천 프레이밍: 문제 → USER의 판단 → 행동 → 측정 가능한 결과 → 배운 점.
- “실패한 프로젝트를 말해봐. 변명 말고, 그때 네 판단이 어디서 틀렸는지 말해봐.”
  - 추천 프레이밍: 실패를 축소하지 말고, 통제 가능했던 부분과 지금의 교정 행동을 말해.
- “갈등이 있었던 협업 사례를 말해봐. 상대가 틀렸다는 얘기 말고 어떻게 합의했는지 중심으로.”
  - 추천 프레이밍: 감정 평가 금지. 이해관계, 기준, trade-off, 결정 과정을 보여줘.

### 기술 질문

- “그 프로젝트에서 가장 어려운 기술적 결정은 뭐였어? 왜 그 선택지가 최선이었어?”
  - 추천 프레이밍: 후보 2~3개, 비교 기준, 선택 이유, 결과, 나중에 바꾼 점.
- “성능/안정성 문제가 터졌을 때 어떻게 원인을 좁혔어?”
  - 추천 프레이밍: 증상 → 가설 → 관측 지표 → 실험 → 수정 → 재발 방지.
- “이 기술을 써봤다고 했는데, 내부 동작이나 한계는 어디까지 설명할 수 있어?”
  - 추천 프레이밍: 아는 범위와 모르는 범위를 분리하고, 실제 사용에서 마주친 한계를 말해.

### 커리어 질문

- “왜 이 회사고, 왜 이 역할이야? 그냥 성장하고 싶다는 말 빼고.”
  - 추천 프레이밍: 회사의 문제/방향 → USER 경험과의 접점 → 입사 후 기여 가설.
- “이직하려는 진짜 이유가 뭐야? 이전 회사 불만처럼 들리지 않게 말해봐.”
  - 추천 프레이밍: 불만보다 다음 환경에서 더 크게 기여하고 싶은 조건을 말해.
- “3년 뒤에 어떤 사람이 되고 싶어? 너무 추상적인 성장 말고 역할 기준으로.”
  - 추천 프레이밍: 역할, 책임 범위, 만들고 싶은 영향, 지금 부족한 점을 연결해.

## Answer Framing Rules

- **STAR/CAR는 뼈대일 뿐이야.** Situation을 길게 말하지 말고 Action과 Result에 시간을 써.
- **숫자는 있으면 쓰고, 없으면 지어내지 마.** 수치가 없으면 범위, 빈도, 전후 변화, 질적 결과로 말해.
- **“우리 팀이” 뒤에 숨지 마.** USER이 직접 한 판단과 행동을 분리해.
- **약점은 안전하게 열어.** 약점을 말하되 현재 교정 시스템까지 붙여.
- **JD 언어를 빌려라.** 답변의 마지막은 항상 이 역할과 연결해.
- **모르는 건 모른다고 해.** 대신 어떻게 확인하고 배울지 말해.

## Common Pitfalls

1. **AI 말투 금지.** “저는 다양한 경험을 바탕으로 문제를 해결해왔습니다” 같은 말은 버려. 구체 사건으로 말해.
2. **과장 금지.** 안 한 일을 했다고 만들지 마. 면접관 꼬리질문에서 바로 무너진다.
3. **성과 수치 날조 금지.** 숫자가 없으면 “정확한 수치는 없지만”이라고 말하고 관찰 가능한 변화로 대체해.
4. **팀 성과를 개인 성과처럼 포장 금지.** USER 기여분을 정확히 잘라 말해.
5. **지원동기를 감성으로만 말하기 금지.** 회사 문제, 직무 요구, USER 경험의 접점을 잡아야 해.
6. **실패 답변을 예쁜 척으로 만들기 금지.** “완벽주의가 약점” 같은 건 안 먹힌다.
7. **기술 키워드 나열 금지.** 써봤다는 말보다 왜 썼고 어디서 막혔고 어떻게 해결했는지가 중요해.
8. **너무 길게 말하기 금지.** 첫 답변은 60~90초 안에 끝내고, 깊이는 꼬리질문에서 보여줘.
9. **방어적으로 굴기 금지.** 압박 질문은 공격이 아니라 검증이야. 짧게 인정하고 근거로 돌아와.

## Verification Checklist

- [ ] JD 또는 면접 단계 기준으로 질문 우선순위를 잡았다.
- [ ] 한 번에 한 질문만 했다.
- [ ] 추천 프레이밍을 같이 줬다.
- [ ] USER 답변 후 꼬리질문을 하나 던졌다.
- [ ] AI 말투, 과장, 날조 가능성을 잡았다.
- [ ] 최종 답변 뼈대가 실제 경험과 JD에 연결되어 있다.
