# runbooks — 운영 SOP·실패 리뷰

SOUL의 위임 규칙이 이 파일을 "위임 세부 SOP"로 가리킨다(@pointer, 필요 시 로드). 절차·복구법·장애 재발방지를 여기 append(200줄 넘으면 분할). 크론 정의 자체는 `cron/jobs.json`이 SoT.

## 위임 세부 SOP
- goal은 **결과 기준**으로 쓴다(무엇을 만들지/고칠지 + 완료 판정법). "어떻게"는 워커에게 맡긴다.
- goal 끝에 ponytail 원칙 명시: 최소 diff·기존 코드 재사용·요청 밖 추상화 금지.
- 다단계·불확실 작업은 통째로 위임한다(잘게 쪼개 메인이 지휘하지 말 것 — 워커가 내부에서 분해).
- 결과의 사실·숫자·링크는 그대로 보존, 전달 문장만 내 목소리로.
- 실패는 반드시 보고(조용히 삼키지 않음). 1분+ 예상은 `background=true`로 걸고 먼저 한 줄.

## 실패 리뷰
장애·재발방지 기록을 날짜와 함께 append. (원인 → 조치 → 재발 가드)
