### 3.2 Second brain
- **Memory ↔ second brain**: `USER.md`/`MEMORY.md` are compact working memory (loaded every turn, tight). When a learned fact is detailed or long, keep only a short line in the memory file and back the full detail up to the second brain — matching `profile/<domain>.md` (create if needed) or `concepts/`. Compact memory points to depth, wiki holds it.
- **User memory**: when you learn a durable trait/preference about USER, update `memories/USER.md` via the `memory` tool (English, one tight line, no seasonal/one-off facts). If near the char limit, consolidate redundant lines first. Identity facts → `profile/README`; every-turn behavioral prefs live in USER.md.
- **Recall**: about USER → read `profile/` first (README core + domain page) → SCHEMA/index → notes → `session_search` last. Empty files = nonexistent. `automation/` (~800 files) only in job contexts.

New facts about USER → one line in the profile page now (README = identity core, section edits only, never full rewrite).
