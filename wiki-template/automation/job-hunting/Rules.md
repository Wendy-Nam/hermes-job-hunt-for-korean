# 구직 규칙 — Source of Truth

## 상태 2단계
- **상태(대분류)**: open / waiting / in-progress / done — TaskNotes 표준 어휘, 보드 컬럼.
- **세부(소분류)**: open{발견·준비} · waiting{지원} · in-progress{서류합격·면접·과제·오퍼} · done{탈락·면접포기·보류·마감}. 세부만 갱신하면 상태는 자동 유도(note-set-field).
  - `준비`: 핏은 좋지만 맞춤자소서/포트폴리오/자료 준비 후 지원해야 하는 공고.


> **이 파일은 검색·필터·판정 규칙의 단일 진실이다. 허브([[README]])를 재구성하더라도 이 파일은 삭제·요약하지 말 것.**
> 크론(수집+판정, 12h)과 스킬(job-match 등)이 이 파일을 직접 참조한다. 2026-07-07 허브 재구성 때 규칙이 소실된 사고 후 분리됨.

## 파이프라인 구조 (수집→판정→입고, 융합 크론)
**공고는 판정 전엔 위키에 없다.** 하나의 크론(`구직 수집+판정`, 08:10·20:10 KST)이 연속 실행:
1. **수집**: `scripts/job-collect.py` — 스크래퍼 5보드(원티드·사람인·잡코리아·링크드인·ATS·웹DDG) → 제목게이트(시니어/연차/무관직) + **트랙게이트**(직군 무관 즉시 컷, SoT=`search-profile.yaml`) + 본문 5년+ 게이트 → 생존자만 `.job-staging.json` 대기열로. 모든 URL은 `.job-seen.json` 장부 등재(재수집 영구 차단).
2. **판정**: LLM이 대기열을 fetch_jd(+vision)로 판정 → `bin/job-stage-commit.py`(유일한 입고 경로)로 ✅/🔧만 `postings/` 노트 생성(적합도 채워짐), 불합격은 거부장부.
3. 위키엔 항상 알짜배기만. 되돌리기: `.backups/`.

## 목표 / Why
- **본질적 목표: "내가 될만한, 비벼볼만한 곳을 찾는 것"** (1순위)
- **최적 조건**: 자격요건에 맞으면서 적합도도 높은 곳 (2순위)
- **제외 조건**: 너무 어드민성 업무를 하는 중소기업, 나랑 안 맞는 도메인
- 흩어진 채용공고를 한 곳에서 수집·비교하고, 우선순위를 정한다.
- 지원 상태를 놓치지 않고 추적한다. (자동 지원은 하지 않음 — 초안만 준비)

## 내 프로필 (본질 — 직무명보다 이게 더 중요)

**USER의 정체성 = 두 얼굴을 가진 사람**

> **둘 중 하나만 맞아도 비벼볼만한 직무다.**

| 얼굴 | 정체성 | 설명 | 해당 직무 예시 |
|------|--------|------|---------------|
| **①** | **AI 자동화 세일즈** | AI 자동화로 리드발굴 할 줄 알면서 발로 뛰는 세일즈 | SDR, BDR, Inside Sales, Tech Sales, Field Sales, AE(주니어) |
| **②** | **시스템 빌더 자동화쟁이** | 비즈니스 문제 해결하는 시스템을 만드는 사람 | Sales Ops, RevOps, GTM Ops, Biz Ops, FDE, AX, Product Ops, PM/PO(운영중심) |

| 차원 | 내용 |
|------|------|
| **핵심 강점** | AI 자동화, 반복업무 효율화, 데이터 기반 의사결정, 영업지원(리드발굴), 프로세스 개선 |
| **문제해결 스타일** | 비즈니스와 기술 사이의 통역사. "이거 왜 아직도 손으로 함?" → 자동화/시스템화 |
| **데이터 철학** | 분석은 수단이지 목적이 아님. 데이터를 보고 개선점을 찾아 고치는 게 본질 |
| **경험** | <본인 대표 경력 — 예: 스타트업 세일즈/옵스, 관련 인턴/프로젝트> 등 — 본인 경력으로 교체 |
| **이력서** | 4종 (ko/en × sales/ops) — 상황에 따라 변형 자동선택 |
| **희망 연봉** | <본인 희망 연봉대로 교체> |
| **언어** | 한국어(원어민), 영어(비즈니스) |

### 판정 프레임워크 (우선순위 순)
0. **USER의 두 얼굴 중 하나에 해당하는가?** (① AI 자동화 세일즈 or ② 시스템 빌더 자동화쟁이) — **게이트 질문. 둘 다 아니면 ❌**
1. **내가 될만한가?** (자격요건·연차·경험 부합도) — 1순위
2. **적합도가 높은가?** (자동화/시스템/프로세스 개선 + 데이터기반 의사결정 + 영업지원) — 2순위
3. **좋은 회사인가?** (브랜드/성장/IT/SaaS/글로벌) — 보너스. 핏 일부만 맞아도 지원 고려
4. **어드민성 중소기업이 아닌가?** — 순수 어드민/행정 업무 중심 중소기업은 제외
5. **도메인이 맞는가?** — USER 경험(IT/SaaS/테크)과 접점 있는 도메인 우선

### 제외 조건 (명확한 것만)
- 순수 어드민/행정 업무만 하는 중소기업
- 마케팅/광고/브랜드/콘텐츠 (본질상 거리)
- 제조/무역/물류/레거시 어드민 (기피 도메인)
- 깡 데이터 분석 (운영/개선 맥락 없는)
- 순수 개발 (비즈니스 맥락 없는)
- 리테일/B2C 소비자 대상
- 인턴 포지션 (더 이상 안 함)

### 직무는 유연하게 봄 (좋은 회사 기준):
- **SDR** (프로스펙팅/리드발굴 있으면 ✅)
- **CSM** (운영/프로세스 개선 요소 있으면 ✅)
- **필드 세일즈** (좋은 회사 + 주니어 가능이면 ✅)
- **PM/PO** (운영/프로세스 개선 중심이면 ✅)
- **AE** (신입/주니어 명시 + 좋은 회사면 ✅)
- **Inside Sales, Sales Ops, RevOps, GTM Ops, Biz Ops** (본질상 항상 ✅)
- **FDE, AX, AI Automation** (본질상 항상 ✅)


## 검색 키워드 프리셋
공고 검색 시 트랙별 키워드. 이력서 변형 표·선택 규칙은 아래가 SoT다(구 JobMatch.md 흡수).

> **SoT 분담 (중복 방지)**: 수집기가 **실제 검색·필터하는 값**(키워드 블록·시니어/연차/제외 정규식·보드)은 `search-profile.yaml`이 **단일 원본**이다. 이 문서는 **판정·전략**(트랙→이력서 매핑·시노님·적합도 기준·우선순위)만 다룬다. 연차/제외의 구체 숫자·목록을 여기서 다시 나열하지 말 것 — `search-profile.yaml`을 고쳐라.
**구분 원칙**: 직접 '파는' 프론트라인 = 세일즈. 세일즈/비즈를 '굴리고 분석하는' 운영·이네이블먼트·데이터·프로덕트 = 옵스.

**공통 필터**
- `신입`, `인턴`, `주니어`, `1년`, `2년`, `무관`, `경력무관`, `경력 0~2년` 우선.
- **`3년 이상`/`3년+`/`3년 플러스`/`3+ years` 등 3년급 이상 연차 요구는 무조건 제외** (1~2년·무관·신입만 허용). `senior`, `lead`, `leader`, `리더급`, `strategic`, `manager`(명시 경력형)도 제외.
- **데이터 분석 게이트**: Data Analyst/데이터 분석 직무는 JD에 **비즈니스 기획·운영·프로세스 자동화 맥락**(운영 개선, 세일즈/비즈 지표 설계, 자동화, RevOps 연계)이 있을 때만 ✅/🔧. **순수 BI/시각화 중심**(Tableau·Power BI·대시보드 제작·정기 리포팅이 업무의 전부)이면 ❌.
- **어드민성 운영 게이트**: 제목이 '오퍼레이션/운영'이어도 실무가 **어드민·사무**(수출입·통관·선적·정산·발주·출하·재고관리·서류·경리·총무·사무보조)면 ❌. 옵스 트랙 = 분석·프로세스 개선·자동화·RevOps 중심.
- **프로필 핏 — 최우선 매칭(예시 프레임)**: 본인 프로필을 한 줄 정체성으로 요약해 여기 적는다(예: "기술 전공 + B2B 영업 경험 + 자동화 빌더" → 기술+GTM 하이브리드). 그 정체성에 맞는 **최적합 직무군**(예: Sales Engineer·Solutions·기술영업)과 **최적합 회사군**(예: 데이터 인프라·AI-native·클라우드)을 나열하면 트리아지가 우선 추천에 쓴다. **로고 크기가 아닌 환경의 질로 판단** — 강한 강소기업도 S/A 가능.
- **제조·하드웨어 도메인 게이트**: **반도체·제조·화학·소재·장비·부품·전자·기계·중공업의 하드웨어 영업**은 부적합 🔧/❌. **예외: 글로벌 빅테크·외국계 대기업(엔비디아·인텔·AMD·ASML·퀄컴·TI 등)의 영업은 유지.** **소프트웨어·SaaS·클라우드·IT솔루션·AI 테크영업을 우선**한다.
- **금융 도메인 게이트**: 회사가 **전통 금융사**(은행·보험·증권·카드·캐피탈·저축은행·신용평가·대부)면 ❌. **예외: 테크 기반 핀테크(토스 등)는 유지.**
- **코디네이터 직무 → 부적합**. 수집단계 제외.
- **언어 게이트**: JD가 본인이 불가한 언어 필수/능통을 요구하면 ❌ ('우대' 표기는 감점만, 컷 아님 — 본인 언어 역량으로 교체).
- **전략기획 직무 → 부적합**. 섞인 제목으로 들어와도 전략기획이 주업무면 ❌. **예외: AX/AI 자동화 맥락의 전략기획(예: 'AX 전략 기획')은 AX 트랙으로 판정한다**.
- **행사·이벤트·스토어/매장 운영 → 부적합**. 수집단계 제외.
- **AX/AI 자동화 트랙 예외**: AI 자동화·AX·업무 자동화 직무 중 **문제해결·비즈니스 운영 중심**(프로세스 개선, AI 도입 기획·운영, 자동화 컨설팅, AX 매니저류)이면 **3~5년 요구도 ❌가 아니라 🔧 검토**로 판정한다(6년+·시니어는 그대로 제외). 단 **순수 기술 중심**(모델 개발·ML 엔지니어링·프로덕션 코딩이 핵심 요건)은 연차 무관 기존대로 급부적합 — 현재 핏 아님.
- **시니어·연차 신호의 구체 패턴(정규식·임계값)은 `search-profile.yaml`이 SoT** (`senior_signals`·`title_exp_min_years`·`body_exp_min_years`). 판정 요지만: **3년+ 경력 요구·시니어·리드·경력형 매니저 → 제외**(1~2년·무관·신입만). `manager`는 `주니어/신입/associate/L1` 완충어 없으면 제외.
- 최근 2주 내 공고는 키워드 폭을 넓혀 우선 긁되, 최종 추천은 같은 연차 필터를 유지한다.
- `AX`라는 검색어에 걸리는 직무도 포함한다.
- 연차가 애매하면 `경력요건 확인 필요`로 메모하고, 일단 키워드 수집은 하되 최종 추천은 보수적으로 한다.

**회사 티어** — 판정 시 적합도와 별개로 노트 `티어` frontmatter에 부여(S/A/B/C/D). (`우선도` 숫자는 티어·트랙·적합도에서 자동 파생 — 손으로 쓰지 말 것):
- **S** 글로벌 테크·유명 유니콘·상장 테크 (쿠팡·토스·Datadog·Notion·OpenAI·Apple급)
- **A** 검증된 강소 — 시리즈 B+ 스타트업, 매출 있는 중견 IT, 이름 있는 외국계 대기업 (채널톡·메가존·로레알급)
- **B** 일반 외국계 (규모 크지 않은 외국계 법인·지사)
- **C** 평범하지만 멀쩡한 국내 회사 (기본값)
- **D** 영세·정보 없음·SI/에이전시/파견/노무·법정의무교육 — 지원 후순위
- 지원 전략: **맞춤 서류는 S/A에 집중**, B/C는 저비용 지원, D는 스킵 또는 여유 있을 때만.

## 변형 자동 선택 규칙 (공고별)
| 공고 조건 | 선택 |
|---|---|
| 한국 보드(원티드/잡코리아/리멤버/사람인)·한글 JD | 한글(ko-*) |
| 링크드인 영문·외국계·글로벌 | 영문(en-*) |
| 세일즈·BD·AM·영업·GTM 직무 | *-sales |
| Ops·PM·운영·전략·프로세스·PMO 직무 | *-ops |

→ 예: 링크드인 영문 Sales 공고 = **en-sales**, 원티드 한글 운영 공고 = **ko-ops**.

**세일즈 트랙 → 세일즈 이력서(*-sales)** (프론트라인 영업)
- Technical sales · Sales · sales development · sales associate · BDR · SDR · AE · account executive · inside sales · field sales
- presales · pre-sales · sales engineer · solution consultant · solutions engineer · customer success · channel sales
- 기술영업 · 솔루션영업 · 영업 · 영업기획 · 영업관리 · 영업지원 · 영업오퍼레이션 · 세일즈오퍼레이션 · 세일즈기획 · 파트너십 · 고객성장

**옵스 트랙 → 옵스 이력서(*-ops)** (운영·분석·프로덕트)

## 이번 분기 핏 규칙 (2026-07-09 추가)
> **이 규칙들은 가이드라인이다. "좋은 회사"(브랜드/성장/IT/SaaS/글로벌/연봉수준)면 핏이 일부만 맞아도 예외적으로 지원 고려할 수 있다.**

- **데이터 분석 단독 직무**는 2년 이상 요구 시 급부적합 처리. 단, 운영/자동화/프로세스 개선 맥락이 있는 데이터 역할은 예외 가능.
- **BI/데이터분석 2년+**는 인턴 직무경험으로 커버 범위가 부족하면 보류. 단, 좋은 회사면 지원 고려.
- **Account Executive(AE)**는 신입/주니어 명시 + 좋은 회사면 지원 가능. 기본은 보류.
- **데이터 사업/마케팅고도화**는 영업/세일즈옵스가 아니라 마케팅·데이터 제품 트랙이면 보류.
- **제안서 작성/IR 중심 사업개발**은 현재 세일즈옵스·자동화 트랙과 보류.
- **리테일기획/B2C 산업도메인/B2C 마케팅 지식**이 핵심인 Product Ops는 보류.
- **광고마케팅/콘텐츠 마케터/브랜드 마케팅** 중심 공고는 세일즈 직함이 섞여 있어도 보류.
- **Product Ops/Growth 중 운영개선·실험·CRM·프로세스 개선**을 보는 공고는 강한 핏. 단 맞춤자소서/포폴 필요 시 `상태=진행중`, `세부=지원준비`로 둔다.
- **제조무역업/레거시 어드민 운영**은 기피 도메인. 제조·무역·물류 쪽 레거시 운영(선적/재고/서류/어드민)은 자동화·개선 비중이 적어 보류. 단, AI/자동화 혁신을 실제로 하는 테크 기업이면 예외 가능.
- **B2C Delivery Operations / 고객인도/차량등록** 등 소비자 대상 딜리버리 운영은 B2B 세일즈옵스 트랙과 맞지 않아 보류.
- **인턴 포지션**은 제외. 인턴/Summer Intern/인턴십 전부 제외 (신입/주니어 포지션 우선).
- **완전한 데이터 분석 + 니치 도메인(게임·이커머스·국방·바이오·동물헬스·전력에너지·반도체유통·공학소재·자동차부품 등)** 조합은 보류. 데이터는 운영·자동화·프로세스 개선 맥락에서만 검토. 단, 좋은 회사(예: 글로벌 IT/SaaS 기업)면 예외 가능.
- **회사명/보드가 모호한 공고** (회사미상·"서울" 등 가명/불명확)는 신뢰도 낮음 → 보류. 지원처 파악이 안 되면 지원할 수 없음.
- **해외영업 / Key Account Manager(KAM)** 포지션은 기존 계정 관리/유지 중심이라 파이프라인 빌딩/운영 트랙과 달라 보류. 단, 좋은 회사면 일부 검토 가능.
- **PM(Product Manager) / Product Owner**는 메인 타깃이 아니지만 운영/프로세스 개선 중심이면 검토. 애매하면 보류.
- **접점이 부족한 니치 산업 도메인**(전력에너지·반도체유통·국방·바이오·동물헬스·공학소재·자동차부품)은 보류. 단, 좋은 회사+성장 가능성 있으면 예외 가능.
- **마감 공고**는 `상태=완료`, `세부=마감` (우선도는 자동 재계산).

## 구조 계약
- **단일 원본 = postings/ 노트** (공고 1행=회사·포지션·보드·적합도·상태·세부·게시일·우선도·메모·링크). 상태만 바꾸면 대시보드 자동 파생, 연쇄수정 없음.
- **우선도 필드** (자동 파생, 최대 7.4): 티어점(S5·A4·B3·C2·D0) + 트랙점(`track_bonus` 0~1.5) + 적합도점(✅0.9·🔧0.5·미판정0.2·❌0). `bin/priority-recalc.py`가 유일 계산자 — 손으로 쓰지 말 것. **설계 노트**: 가중합이라 트랙점 1.5로 인접 티어 역전이 가능하다(예: B+선호트랙 > S+저적합) — 선호 직무를 티어보다 위로 올리려는 의도된 동작. 티어 절대우선을 원하면 track_bonus를 0으로.
- 대시보드(Kanban)는 파생 뷰이자 편집면(드래그→공고DB 역반영). 규칙은 이 파일(SoT).
- 수집=job-collect.py(no_agent), 판정=구직 트리아지 크론.

## 비타깃 제외 (수집단계 자동)
- 순수 개발직·무관직은 **수집단계 자동 제외**(제목 기준, job-collect). **제외 목록 SoT = `search-profile.yaml`의 `exclude_roles`** — 여기서 나열 안 함. 판정 시에도 세일즈/옵스 아니면 ❌. 단 이미 지원/전형 건은 보존.

## 우선순위 (중요한 것 먼저 지원)
- **1순위 = `티어`** (S→A→B→C, D 제외). 좋은 회사가 먼저다 — **S/A는 🔧(보완후지원)여도 보완해서 지원할 가치가 있다.**
- **선호 서열(사용자 확정 2026-07-10)**: ①외국계 대기업(영업·옵스 모두) ②AI 자동화 ③자동화 중심 옵스 ④기술영업 ⑤일반 영업(SMB). 우선도 숫자에 트랙 가산점(`search-profile.yaml` `track_bonus`)으로 반영됨 — C티어라도 AI 자동화면 일반 외국계 평직무보다 위로 정렬된다.
- 2순위 = `적합도`(같은 티어 안에서 ✅ → 🔧), 3순위 = 게시일 최신. ❌는 스킵.
- C는 ✅만 저비용으로 지원, D는 스킵(여유 있을 때만).
- 각 공고의 `키워드` 필드 = 어느 검색어로 왔는지(핏 추적).
- 숫자 `우선도`(0~7.4) = **티어+트랙+적합도의 자동 파생 정렬키**(`bin/priority-recalc.py`가 유일 계산자, 손으로 쓰지 말 것). Bases 정렬은 이 숫자로.
- Bases/TaskNotes에서 티어·적합도·상태로 정렬/필터해 **[S/A] open부터** 본다.
