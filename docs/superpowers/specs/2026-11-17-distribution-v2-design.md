# 배포용 v2 설계

사용자 요청: 오늘 VPS에 적용한 개선을 레포에 반영하고 Composio와 google-workspace 메일 경로를 모두 지원한다. 현재 VPS는 google-workspace를 선택한다.

## 선택

공통 job-application 스킬과 백엔드별 참조 문서를 둔다. 별도 스킬 두 개로 업무 규칙을 복제하거나 인증 실패 시 다른 계정·백엔드로 자동 전환하지 않는다. 메일은 명시적으로 google-workspace, composio, none 중 선택하며 검색·읽기만 한다. 선택된 백엔드의 인증 실패는 보고하고 노트 기반 리마인더로 제한한다.

## 배포 범위

- VERSION 2.0.0 후보와 변경 기록. 공개 태그·릴리스 발행은 별도다.
- 앱·상태·5개 스킬 분리 구조와 기존 legacy 설치 호환을 유지한다.
- 설치 dry-run, 관리 파일 목록·해시, 코드 교체 전 백업, 개인 설정 보존, 관리 파일만 제거하는 안전한 제거기를 제공한다.
- HERMES_HOME과 구직 루트를 명시한다. 다른 구직 루트로의 재설치는 자동 마이그레이션하지 않는다.
- 빈 구직 폴더에만 Rules·README·경력 입력 서식·TaskNotes 칸반을 보강한다. 기존 칸반과 개인 자료는 덮지 않는다.
- 검색 프로필은 설치 입력으로 선택한다. AI 교육→자동화 PM→GTM RevOps는 예제 프로필로 제공하며 실제 경력·회사별 판단·Discord 채널·API 키는 배포 소스에 넣지 않는다.
- 기본 모델 예시는 사용자가 지정하도록 비워 둔다. OmniRoute 설정은 예제로 분리하고, 기존 VPS 설정은 유지한다. 공개 분석은 설정된 때만 수행하고, 개인 데이터 판정용 모델을 지정하기 전 크론을 활성화하지 않는다.
- 크론은 Hermes API로 등록한다. google-workspace 선택 시 해당 스킬을 함께 로드한다. 결과 채널은 설치자가 지정한다.
- 과거 지원 기록 정리는 배포 기본 동작에 포함하지 않는다. 이번 VPS의 사용자 요청에 한정된 작업이다.

## 검증

백엔드 선택·설정 보존·잘못된 백엔드 거부, dry-run 무변경, 코드 백업과 개인 파일 보존, 관리 파일 제거 경계, TaskNotes 칸반 생성·기존 칸반 보존, 모델 미설정 시 자동 실행 차단, 기존 회귀 테스트를 확인한다. CI에서 native 테스트를 실행한다. 현재 VPS는 google-workspace 읽기와 구직 크론 설정만 갱신하고 개인 검색 조건·채널·과거 정리 결과를 유지한다.
