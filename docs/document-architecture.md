# 이력서·포트폴리오 자료 구조

원문을 보존하고, 직무별 제출본은 검증된 자료에서 선택해 만듭니다. 설치 코드는 사용자의 경력·추천 직무를 포함하지 않습니다.

```text
resume/
  sources/                     # 원본 PDF·프로필·웹 자료와 수집 시점, 변경하지 않음
  source_catalog.md            # 파일·URL·해시·출처 ID
  evidence_ledger.md           # 주장과 원문 위치, 직접 측정·추정·후기 구분
  claim_conflicts.md           # 날짜·수치 차이와 확인 상태
  materials/
    ko/                        # 국문 통합 자료 4종
    en/                        # 영문 통합 자료 4종
  document_profiles.yaml       # 같은 자료에서 직무별 사례·표시 항목 선택
outputs/                       # 재생성 가능한 HTML·PDF
```

각 언어 폴더에는 `master_resume.md`, `fit_evidence.md`, `role_contexts.md`, `portfolios.md`가 있습니다. 국·영문은 별도 표현을 가지되 같은 출처 ID로 연결합니다. 번역으로 직위·기여·고용형태·성과 수준을 높이지 않습니다.

## 프로필

기본 세트는 AI 교육·Enablement, 자동화 실무·솔루션 PM, GTM Engineering·RevOps의 3가지입니다. 국·영문으로 6개 제출본을 만들되 마스터 6개를 따로 관리하지 않습니다. 직무는 예시이며 사용자 경력에 맞춰 이름과 개수를 바꿉니다. 솔루션 엔지니어·Problem Solver는 필요할 때 자동화 계열에서 파생합니다.

`resume/document_profiles.example.yaml`을 복사해 `document_profiles.yaml`을 만듭니다. 프로젝트 이름은 해당 언어의 `portfolios.md` 제목과 정확히 일치해야 합니다. 잘못된 경로·언어·누락/중복 프로젝트는 오류로 종료하며 다른 이력서로 대체하지 않습니다.

```bash
job-hunt documents --profile ai-education-ko --company "검토용" --position "AI 교육" --only resume --pdf
job-hunt documents --profile ai-education-en --company "Preview" --position "AI Enablement" --only portfolio --pdf
```

`preserve_order: true`는 원문 핵심역량과 선택한 사례의 순서를 보존합니다. `brief_experiences: true`는 경력란에 원문의 `담당 업무` 한 줄만 표시하고 상세 성과는 회사 프로젝트에서 보여줍니다. 담당 업무가 비어 있으면 임의로 문장을 자르지 않고 오류로 종료합니다. `resume_projects`와 `portfolio_projects`로 선택 순서를 명시합니다. 원문에 있는 핵심역량을 새 역량명·도구 목록·성과 숫자로 바꾸지 않습니다. 선택 결과의 문장은 원문 자료를 그대로 사용합니다.

프로필 없이 기존 명령과 `--materials-dir`도 유지됩니다. 업그레이드는 사용자 자료를 덮어쓰지 않습니다. 새 템플릿은 앱의 assets와 공개 배포본에서 확인할 수 있습니다.

## 사례의 내용 구조

경력 불릿과 프로젝트는 **상황 → 문제 → 본인의 해결 → 임팩트**를 연결합니다. 글 길이에 맞춰 한 문단으로 연결할 수 있지만, 결과 숫자만 남기고 맥락을 삭제하지 않습니다.

- 상황: 대상·환경·업무 흐름은 무엇이었나?
- 문제: 어떤 병목·제약·사용자 어려움을 확인했나?
- 해결: 본인이 무엇을 설계·구현·설명·검증·인계했나?
- 임팩트: 무엇이 달라졌고, 어떻게 확인했나?

`portfolios.md`는 `상황`, `문제`, `해결`, `임팩트` 필드를 지원합니다. 기존 `배경·문제`, `성과`도 호환됩니다. 미확인 맥락은 추정해 채우지 않습니다. 없는 값은 생략하고 자료 보강 목록에 남깁니다. 정성 변화도 유효한 임팩트이며, 추정·후기는 해당 성격을 보존합니다.

포트폴리오는 언어별 통합 사례집에서 직무별로 발췌합니다. 이력서에는 보통 2~3개, 포트폴리오에는 3~5개를 선택하되 고정 페이지 수 때문에 문제·기여를 지우지 않습니다. 교육 직무도 최근 프리랜스만 보지 않고 교육 봉사·사용자 지원·문서·오픈소스·연구 온보딩 등 원문 근거를 확인합니다.

## 공개 배포와 개인 운영의 경계

공개 저장소: 코드, 빈 입력 양식, 일반 프로필 예시, 스킬, 가이드, 합성 테스트.
개인 저장소: 실제 원본, 통합 경력, 연락처, 지원처, 생성 문서, 모델·메일·알림 설정.

배포판의 원본 스킬과 템플릿을 수정합니다. 일반 문서 출력 과정에서는 코드·원본을 고치거나 테스트를 실행하지 않습니다. 외부 제출은 지원 정책과 별도 권한을 따릅니다.


## 하나의 경력 마스터에서 동기화

`resume/career_master.md`를 쓰는 설치에서는 경력·사례·직무 맥락의 국·영문 6개 구역과 판단 프로필·문서 프로필·공개 검색 조건 3개 구역을 한 파일에서 관리합니다. 빈 구조는 `resume/career_master.example.md`에 있습니다.

```bash
job-hunt career-sync --write
job-hunt career-sync --check
```

`<!-- career:구역명 -->`과 `<!-- /career:구역명 -->` 사이가 입력입니다. 동기화는 언어별 자료 8개, 기본 국문 자료 4개, 판단 프로필·문서 프로필·앱 검색 조건 3개를 생성합니다. 에피소드와 적합도 근거는 같은 프로젝트 파서로 사례집에서 만듭니다. 사례의 상황·문제·해결·임팩트를 별도로 다시 작성하지 않습니다.

변경된 파생 파일은 비공개 백업 후 교체합니다. 파생 파일을 따로 수정했다면 덮어쓰지 않고 정본에 합치도록 오류를 냅니다. 마스터나 경로가 잘못된 경우 쓰기 전에 중단합니다. 새 사용자에게 통합 마스터를 강제하지 않으며 기존 자료 폴더·명령은 유지합니다.

이력서·면접·공고 판정 스킬은 일치 검증 후 같은 자료를 참조합니다. 공개 수집기는 마스터를 읽지 않고 공개 검색 조건만 읽습니다. 검색 조건에는 경력·연락처 필드를 넣을 수 없으며, 무료 모델의 공고 payload는 기존 공개 필드 허용 목록을 유지합니다.

## 경력 요약과 회사 프로젝트

경력사항에는 기간, 소속, 직책과 담당 영역을 짧게 둡니다. 주요 프로젝트는 직무에 맞는 회사 수행 사례 보통3개를 고르고, 대상, 구현, 본인 기여와 결과를 구체적으로 남깁니다. 개인 프로젝트, 연구, 해커톤과 오픈소스는 대외활동 및 관련 경험으로 분리합니다. 원문 전체는 통합 마스터와 포트폴리오에 보존합니다.

프로필의 `skills`는 `label`과 `value`를 가진 행 목록입니다. 직무에 실제로 사용한 기술을 골라 순서를 정합니다. `plain_punctuation: true`는 본문 중간점을 쉼표로 바꾸며 직책 및 소속 줄과 링크 주소는 보존합니다. `highlight_terms`에는 실제 본문에 있는 주요 수치나 키워드만 지정합니다. 목록과 표의 해당 단어만 600 두께로 표시하며 제목이나 전체 문단을 굵게 만들지 않습니다.

```yaml
brief_experiences: true
plain_punctuation: true
skills:
  - label: 데이터 운영
    value: SQL, Excel, 데이터 정규화
highlight_terms: [CRM, SQL]
```

관측 수치, 신청 인원, 참석 규모, 누적 시간과 후기 수의 분모를 구분합니다. 강한 사례의 설명을 살리되, 모든 수치를 모든 직무의 이력서에 반복하지 않습니다. 공개 GitHub 기술 자료는 실무 성과의 보조 증빙이며 README만 본 저장소를 실제 계정에서 검증한 시스템으로 표현하지 않습니다.

### 표 격자와 핵심역량 강조

국문 서식의 3열 표는 `three-column` 클래스와 세 개의 `<col>`을 둔 `<colgroup>`을 사용합니다. 날짜22%, 항목30%, 설명48%를 공유하고, 보유기술의 행 제목도22%를 사용합니다. 셀 여백은 공통 CSS 변수로 관리합니다. 서로 다른 표에 인라인 열 너비를 추가하지 않습니다.

핵심역량은 원문을 유지하면서 앞쪽 이름만 `highlight_terms`에 넣어 세미볼드600을 적용할 수 있습니다. 예를 들어 이름이 `업무 분석`이고 뒤에 설명이 붙으면 해당 이름만 등록합니다. 전체 설명 문장을 강조 목록에 넣지 않습니다.
