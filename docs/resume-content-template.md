# 직무별 이력서 내용 틀

국문 요약형은 한 줄 소개, 핵심역량, 경력, 학력·자격, 주요 프로젝트, 대외활동, 보유 기술 순서로 구성합니다. 아래는 문장의 내용과 역할을 정하는 틀입니다. 실제 경력·기간·직위는 원본대로 유지합니다.

## 1. 인적사항과 한 줄 소개

이름 / 이메일 / 연락처 / 실제 포트폴리오·프로필 링크

**한 줄 소개:** `<누구의 어떤 업무 문제>`를 `<직접 해본 방식>`으로 해결하는 `<직무 방향>`.

사진·생년월일·상세 주소는 제출처가 요구하는 경우에만 선택합니다.

## 2. 핵심역량 및 업무 강점

역량명 뒤에 실제 수행 내용을 붙입니다. 도구 목록이나 모든 성과 숫자를 이 칸에 몰아넣지 않습니다.

사용자 원문의 핵심역량은 마스터 자료에 **역량명과 설명을 그대로 보존**합니다. 명시적으로 `summary_points`를 설정한 직무 프로필은 원문 근거에 맞춘 별도 이름과 설명을 출력합니다. 미설정 시 원문을 사용합니다. 도구와 숫자만 나열해 업무 역량의 설명을 대체하지 않습니다. 원문이 없는 사용자에게만 다음 입력 질문을 제공합니다: 어떤 문제를 발견했는가, 직접 무엇을 만들었는가, 누구와 협업했는가, 어떻게 운영·인계했는가.

## 3. 경력 사항

| 근무 기간 | 회사 / 직위·고용형태 | 주요 업무 |
|---|---|---|
| `<시작 ~ 종료>` | `<공식 회사·직위, 인턴/정규/프리랜스 등>` | `<업무 영역 한 줄>`<br>`<직접 수행한 업무 2~3개>` |

경력 표에는 기간, 공식 직책과 담당 업무 영역을 간결하게 둡니다. 상세 구현과 성과는 주요 회사 프로젝트로 옮기며 원문을 삭제하지 않습니다. 숫자는 해당 행동의 범위·결과를 설명할 때 넣습니다. 실무 강의, 학부연구생, 교육 과정, 개인 프로젝트의 성격을 구분합니다.

## 5. 주요 프로젝트

| 기간 | 프로젝트명 / 역할 | 내용 |
|---|---|---|
| `<기간>` | `<이름 / 기획·구현·PM·운영 등 본인 범위>` | `<대상과 업무 문제>`를 해결하기 위해 `<직접 설계·구현한 내용>`을 수행. `<실제 사용 범위와 결과>`로 연결 |

주요 프로젝트에는 회사에서 수행한 대표 사례를 둡니다. 개인 프로젝트와 연구, 해커톤은 대외활동으로 분리합니다. 문제, 직접 기여, 결과는 문장으로 연결하고 반복 소제목은 붙이지 않습니다. 요약형은 강한 사례 2~3개를 고릅니다. 상세 포트폴리오에는 운영·인수인계, 사용 후기·영상·원문 같은 근거를 덧붙입니다. 추정과 사용자 후기를 직접 측정 지표로 바꾸지 않습니다.

## 6. 대외활동 및 관련 경험

| 기간 | 활동·기관 / 역할 | 수행 내용 |
|---|---|---|
| `<기간>` | `<발표·교육 / 발표자·강사>` | `<설명한 주제·실습 대상·직접 진행 내용>` |
| `<기간>` | `<오픈소스·커뮤니티 / 기여 역할>` | `<모듈·문서·이슈 대응·커뮤니티 기여>` |
| `<기간>` | `<연구·교육 과정 / 참여 역할>` | `<연구·구현·코드 리뷰·협업 경험>` |
| `<기간>` | `<콘텐츠·홍보대사 / 제작·피드백 역할>` | `<콘텐츠 주제·사용자 피드백 등 실제 활동>` |

활동명만 적지 않고 직무와 연결되는 수행 내용을 적습니다. 활동명에는 기관·행사와 실제 역할을 적어 연사·운영자·참가자를 구분합니다. 설명은 직접 한 행동과 대표 성과를1~2문장으로 연결합니다. 도구 나열과 반복 설명을 먼저 줄이고, 해당 직무의 판단에 필요한 수치와 그 범위는 남깁니다. 사용자가 확정한 설명은 직무별 사본에서도 동일하게 유지합니다. 요약형은 한 표로 묶습니다. 상세형은 **교육·코칭 / 오픈소스·커뮤니티 / 연구 경험 / 콘텐츠**로 나눌 수 있습니다.

## 출력 자료와 연결

자동 출력의 요약 입력은 `resume/role_brief.template.md`, 전체 자료는 `resume/master_resume.md`, 프로젝트는 `resume/portfolios.md`를 사용합니다. 역할별 사본은 4종 자료를 갖춘 폴더로 선택합니다. 원본·지표·차이는 source_catalog, evidence_ledger, claim_conflicts에 남깁니다.

통합 자료·6종 직무 프로필·포트폴리오 발췌 구조는 [문서 자료 구조](document-architecture.md)를 따릅니다.

## 서식과 분량

공통 HTML 서식의 글꼴과 글자 크기를 유지합니다. 국문 3열 표는 기간22%, 항목30%, 설명48%의 같은 격자와 상하1.2mm 여백을 사용합니다. 학력 등4열 표와 포트폴리오 목록은 각 정보 구조를 유지합니다. 표의 상단선은 제목 아래에 별도로 띄우지 않고 표에 붙입니다. 긴 표는 행 단위로 이어지고 다음 쪽에 열 제목을 반복합니다.

영문 이력서는 Arial 계열 산세리프와10.2pt 본문을 사용합니다. 이름과 섹션 제목은 가운데 정렬하고, 경력 제목은 `회사명 | 직책`과 오른쪽 날짜로 구성합니다. 회사 설명·소속·고용형태는 아래 이탤릭 줄에 표시합니다. 핵심역량은 Key Strengths, 경력은 Professional Experience, 기술은 Technical Skills로 구분하며 빈 섹션은 생략합니다. 폰트 설치 상태와 내용에 따라 줄바꿈과 쪽수가 달라질 수 있으므로 실제 PDF를 확인합니다.

핵심역량의 앞쪽 이름과 주요 수치는 `highlight_terms`에 등록하면600 두께로 표시됩니다. 설명 전체를 강조 목록에 넣지 않습니다. 본문 중간점 대신 쉼표를 쓰려면 `plain_punctuation: true`를 사용합니다. 직책·소속 구분과 링크 주소는 유지됩니다.

긴 기관명과 직무명은 단어 단위로 흐르게 두고, 제목과 날짜가 겹치지 않도록 공통 서식의 줄바꿈을 사용합니다. 특정 인물이나 문구에 맞춘 강제 줄바꿈을 배포 템플릿에 넣지 않습니다.

국문 요약 제출본은2쪽을 우선합니다. 넘치면 반복 설명과 관련성이 낮은 활동부터 줄이고, 상세 구현과 도구는 마스터·포트폴리오에 보존합니다. 역할과 실제 기여, 대표 성과를 지우거나 글자 크기를 낮추어 맞추지 않습니다. 자동 절단이나 고정 쪽수 보장 기능은 없습니다. PDF의 실제 쪽수, 표 헤더 반복, 제목·날짜·숫자의 잘림을 확인한 뒤 제공합니다.
